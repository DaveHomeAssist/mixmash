# Lot renderer backend

FOH-V01b technical component, 2026-10-04. The backend is connected through an explicit 3D preview in Menu → Camera. The classic renderer remains the default. [FB-01](FEATURE_BRIEFS.md#fb-01-continuous-orbit-and-camera-presets) and the [renderer contract](RENDER_CONTRACT.md) remain the target. Input, camera controls and automatic Canvas 2D fallback are implemented; complete scene parity and final art/device acceptance remain required.

## Implementation

- [`lot-camera.mjs`](../lot-camera.mjs) owns continuous yaw, 15–85 degree orbit pitch, stable 90 degree Plan, bounded zoom, HUD-aware framing, CSS projection and ground ray inversion. It uses logical tiles and preserves canvas offsets. FOH/Stage use explicit stage-relative authored eye positions; their physical calibration remains pending.
- [`lot-models.mjs`](../lot-models.mjs) authors stage, PA, bar, restroom and representative guest geometry, plus dimensional light/gate/exit context. Geometry stays inside authoritative equipment footprints through all four rotations. Metal/paint/plastic materials have explicit roughness and metalness. These simplified samples are technical placeholders, not accepted realistic assets.
- [`lot-renderer.mjs`](../lot-renderer.mjs) consumes the existing scene fields, draws daylight/show lighting, highlights, engine sight sets and a declared representative population. It returns depth picks resolved to the current layout and exposes camera/resource diagnostics. It has no economy actions, persistence or independent animation clock.

The backend accepts Oak St. Lot only. The application facade in [`board-adapter.mjs`](../board-adapter.mjs) selects the existing board for other rooms, initialization failure or context loss. It retains the latest scene and existing input canvas; the 3D canvas owns presentation only. A status message and Camera dialog provide retry. Context restoration resumes the same show. No camera or renderer preference is inserted into a save.

## Dependency and provenance

Three.js **0.184.0** is exact-pinned in the package and lockfile. Its MIT license is retained in [`vendor/three/LICENSE`](../vendor/three/LICENSE). Browser modules are served from this site, with no CDN or new content-security-policy exception. `npm ci` validates the package integrity; `npm run check:front-of-house-vendor` verifies byte equality of both committed modules and license. `npm run vendor:front-of-house` reproduces the copies after an intentional dependency update.

All sample geometry/materials are newly authored project code, generated by Codex for Front of House. No archive assets, external textures, branded models, purchases or commissions are included. `MODEL_METADATA` records authoring source, logical units, pivot and forward vector. Physical scale, calibrated eye height, convincing human anatomy, animation, texture detail and visual acceptance remain open. There is no claim that the technical sample meets the realistic art direction.

## Verification and remaining work

`node --test front-of-house/test-lot-camera.mjs` covers ground round trips at yaw 37/135, pitch 15/85, named zoom levels and CSS offsets; outside-lot rejection; safe-area framing at desktop/phone/ultrawide sizes; bounds and Plan; anchored zoom; and mesh containment/orientation against engine footprints.

`npm run smoke:front-of-house-lot` exercises real WebGL in Chromium: drawing and current-object picking, immutable scene inputs, eight view/light captures, phone framing, actual context loss/restoration and 20 idempotent create/dispose cycles with stable warm resource counts. The screenshot directory is emitted by the command. Software-rendered browser evidence does not certify physical device performance or art quality.

`npm run smoke:front-of-house-3d` runs the actual game through orbit, pinch during placement, cancellation, one-tap placement/Undo, touch inspection, accessible camera controls, context and missing-module fallback, viewport fit and mid-show reload. It compares every settlement field and the complete resulting game state between renderers at a fixed settlement timestamp.

The [lot-sample-2 candidate](LOT_SAMPLE.md) adds perimeter/incident cues, idle guest sway, live reduced motion and coherent authored eye positions. It still needs close-up realistic refinement, walking/queue poses, physical calibration, full HUD/high-DPI/device performance and human acceptance. These remain FOH-V01/FOH-P01 work. No engine migration to Unreal is included.
